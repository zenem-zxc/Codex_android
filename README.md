# Codex Android Remote

Android-клиент для удалённой работы с локальными сессиями Codex на Windows.

Проект предназначен для личного использования: телефон подключается к
компьютеру, на котором работает текущая конфигурация Codex и выбранный
провайдер. Приложение не создаёт отдельную копию агента и не переносит
историю в облако.

> **Статус: ранний прототип.** Базовые сценарии Windows bridge проверены
> локально. Android-приложение ещё не реализовано.

## Идея проекта

```text
Android-приложение
        │
        │ защищённое соединение через частную сеть
        ▼
Windows bridge
        │
        │ локальный JSON-RPC / stdio
        ▼
Codex App Server
        │
        ▼
существующие проекты, сессии и текущий API-провайдер
```

Источником истины остаётся Codex на Windows. Телефон выступает клиентом
управления, а не независимым чат-приложением.

## Что уже работает

- обнаружен установленный `codex-cli 0.164.0-alpha.11.1`;
- подтверждён запуск локального `codex app-server`;
- подтверждены запросы `initialize` и `thread/list`;
- локальный App Server видит существующие сессии Codex;
- реализован прозрачный Windows bridge;
- bridge пересылает JSONL-сообщения в обоих направлениях;
- добавлена авторизация клиента токеном;
- добавлен автозапуск bridge при входе в Windows;
- текущая конфигурация Codex и провайдер не изменяются.

Локально через bridge также проверены чтение истории, `thread/resume`,
`turn/start` и потоковый ответ; созданный постоянный диалог появился в
списке истории. Одновременный resume уже открытой сессии может завершиться
ошибкой `already has an active writer`. Approvals, вложения, восстановление
соединения и связь между устройствами пока не проверены.

## Windows bridge

Bridge запускает локальный App Server только после подключения клиента:

```powershell
python .\pc_bridge\bridge.py --host 127.0.0.1 --port 8765
```

После подключения bridge передаёт без изменения:

- JSON-RPC-запросы;
- ответы App Server;
- потоковые уведомления;
- запросы подтверждения действий;
- сообщения об ошибках;
- новые методы протокола, которые появятся в будущих версиях.

Bridge не изменяет конфигурацию и файлы самостоятельно. Однако
аутентифицированный клиент может отправлять через него запросы Codex,
в том числе изменяющие файлы и историю. Bridge не фильтрует RPC.
В частности, сам bridge не изменяет:

- `%USERPROFILE%\.codex\config.toml`;
- auth-файлы;
- настройки API-провайдера;

### Автозапуск в Windows

```powershell
powershell -ExecutionPolicy Bypass `
  -File .\pc_bridge\install_autostart.ps1
```

Удаление автозапуска:

```powershell
powershell -ExecutionPolicy Bypass `
  -File .\pc_bridge\uninstall_autostart.ps1
```

Токен создаётся автоматически и хранится локально:

```text
%USERPROFILE%\.codex\bridge.token
```

Токен нельзя публиковать в GitHub, отправлять в открытые чаты или добавлять
в исходный код.

## Удалённая проверка без Android

До появления Android-приложения добавлен экспериментальный CLI-клиент.
Соединение между разными устройствами пока не проверено. По умолчанию
`127.0.0.1` доступен только на самом ПК.

В первом окне запустите bridge:

```powershell
python .\pc_bridge\bridge.py --host 127.0.0.1 --port 8765
```

Во втором окне получите список сессий:

```powershell
python .\tools\remote_client.py `
  --token-file "$env:USERPROFILE\.codex\bridge.token" `
  --list
```

Создать новый постоянный диалог и отправить сообщение:

```powershell
python .\tools\remote_client.py `
  --token-file "$env:USERPROFILE\.codex\bridge.token" `
  --new `
  --cwd "D:\Pyfiles\Codex_android" `
  --message "Привет. Это проверка удалённого управления через bridge."
```

Клиент выведет `NEW_THREAD`, потоковый ответ модели и `STATUS=completed`.
Созданный диалог должен появиться в истории Codex. Отправка в существующий
диалог выполняется явно:

```powershell
python .\tools\remote_client.py `
  --token-file "$env:USERPROFILE\.codex\bridge.token" `
  --thread-id "<THREAD_ID>" `
  --message "Продолжи работу."
```

Не запускайте `--message` с `--thread-id`, если не хотите изменять историю
выбранной сессии. Новый диалог создаётся в режиме `read-only`; существующая
сессия использует свои настройки. CLI пока не поддерживает интерактивные
запросы подтверждения и прерывает работу, если они поступят.

## Рекомендуемое подключение телефона

Возможный вариант для дальнейшей проверки:

```text
Android → Tailscale или ZeroTier → Windows bridge
```

Bridge передаёт **токен и все данные открытым текстом**. Не открывайте порт
напрямую в публичный интернет и не используйте обычную LAN без защищённого
туннеля. Для доступа с другого устройства потребуются защищённый туннель,
привязка bridge к доступному интерфейсу и соответствующее правило файрвола;
пока это не настроено и не проверено.

В будущем bridge должен получить полноценный TLS, pairing устройств,
ограничение разрешённых устройств и журналирование подключений.

## Быстрая проверка App Server

Read-only probe проверяет, что локальный App Server запускается и отвечает:

```powershell
python .\tools\probe_app_server.py
```

Проверка отправляет только `initialize` и `thread/list`. Она не отправляет
сообщения агенту, не изменяет файлы и не запускает команды в проекте.

## Ограничения и безопасность

- Проект не использует официальный ChatGPT Remote.
- Текущий сторонний API-провайдер не заменяется.
- API-ключи и токены не должны попадать в репозиторий.
- Bridge предоставляет доступ к рабочей среде Codex, поэтому его нельзя
  открывать без аутентификации.
- Bridge не обеспечивает подтверждения опасных операций самостоятельно:
  они зависят от настроек Codex и возможностей подключённого клиента.
- Одновременное управление одной сессией несколькими устройствами пока
  не поддерживается.
