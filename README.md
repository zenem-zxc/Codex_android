# Codex Android Remote

Исследовательский прототип Android-клиента для удалённого управления
локальным Codex App Server на Windows.

## Текущий результат исследования

Пустой репозиторий не содержал Android-проекта или серверного компонента.
Локально обнаружено:

- `codex-cli 0.164.0-alpha.11.1`;
- `codex app-server` поддерживает stdio и WebSocket-транспорт;
- сгенерирована экспериментальная JSON-схема протокола в
  `.research/app-server-schema/`;
- в протоколе присутствуют `initialize`, `thread/list`, `thread/resume`,
  `thread/read`, `thread/items/list`, `turn/start`, `turn/interrupt`,
  `thread/attachment/add` и методы удалённого управления/паринга;
- текущая конфигурация использует провайдера `cheapvibecode`, поэтому
  прототип не меняет `config.toml`, провайдера или auth-файлы.

Наличие метода в локальной схеме не доказывает, что он разрешён текущей
сборкой, конфигурацией или сетевым режимом. Совместимость с сессиями VS Code
и диалогами Work должна быть проверена отдельными запросами и не считается
подтверждённой заранее.

## План архитектуры

1. **Windows bridge** — локальный `codex app-server`, запускаемый на ПК.
2. **Relay** — небольшой защищённый WebSocket/TLS-шлюз, который не хранит
   API-ключи и разрешает только выбранный набор App Server RPC.
3. **Android client** — Kotlin + Jetpack Compose + Coroutines/Flow.
4. **Security** — одноразовое спаривание, короткоживущий токен,
   allowlist устройств, TLS, явные подтверждения для команд и изменений.
5. **State** — на телефоне только кэш UI; источником истины остаётся
   App Server и его локальная история.

Не следует открывать `codex app-server` напрямую в интернет. Relay должен
изолировать транспорт, а опасные запросы — `command/exec`, изменения файлов,
разрешения и вложения — проходить через явное подтверждение.

## MVP

1. Поднять relay на Windows.
2. Выполнить `initialize` и read-only `thread/list`.
3. Открыть поток через `thread/resume` или `thread/read`.
4. Реализовать `turn/start` и поток уведомлений.
5. Добавить восстановление WebSocket и idempotency.
6. Только после этого добавить Compose UI, вложения и подтверждения.

## Ограничения

- Официальный Remote и вход через ChatGPT не используются.
- Текущий сторонний провайдер не заменяется.
- Поддержка исходных диалогов ChatGPT Work пока не подтверждена.
- Сессии VS Code считаются продолжимыми только после фактической проверки
  `thread/list`/`thread/resume` на этой машине.

## Первый проверяемый шаг

```powershell
python tools/probe_app_server.py
```

Команда запускает отдельный локальный app-server через stdio, отправляет
только `initialize` и `thread/list`, печатает результаты без токенов и не
редактирует пользовательскую конфигурацию.

## Компонент для Windows

В `pc_bridge/` добавлен прозрачный TCP-релей:

```powershell
python .\pc_bridge\bridge.py --host 127.0.0.1 --port 8765
```

Он запускает отдельный `codex app-server --stdio` на каждое подключение и
пересылает JSONL-сообщения без изменения. Поэтому через него проходят не
только чатовые запросы, но и уведомления, approvals, отмена, файлы,
вложения и новые методы протокола. Это транспортный прокси, а не второй
агент и не отдельная история.

Автозапуск при входе в Windows:

```powershell
powershell -ExecutionPolicy Bypass -File .\pc_bridge\install_autostart.ps1
```

Для первого соединения Android должен использовать частную VPN-сеть
(предпочтительно) или локальную LAN. Открывать этот необработанный TCP-порт
в публичный интернет нельзя.
